# Світлина — правила роботи

- Простими словами, українською. «Спершу дай відповідь, нічого не змінюй» — лише відповідай; зміни після «згодна». Перед великими або незворотними кроками питай.
- Жодних особистих подробиць власниці в коді, документах, комітах і релізах. Документація коротка й описує актуальний застосунок.
- Після кожної зміни перевіряти, чи треба оновити README, опис репозиторію на GitHub і нотатки релізу (`.github/release-notes.md`).
- Без дозволу на інтернет, мінімум дозволів (типово — лише фото й відео). Українська й англійська, без русизмів і російських слів.
- Цілісність метаданих: дата копії = дата оригіналу, метадані копіюються повністю, оригінали із загальних папок застосунок сам не видаляє. Кожна дія редагування — з тестом «зберегти → прочитати → порівняти».
- Межі за часом: дії з одним фото ≈1 хвилина, миттєві дії 1–2 с; оцінка часу до старту, «Зупинити» на будь-якому етапі.
- Моделі ШІ лише з офіційних джерел, із закріпленою версією, контрольною сумою й перевіреною ліцензією (некомерційні не беремо); усе — в `NOTICE.md`. Код з Iris Gallery (Apache 2.0) і Fossify Gallery (GPL-3.0) — лише із зазначенням у `NOTICE.md`.
- Важливі зміни перевіряє незалежний аудит окремим агентом; перед релізом для людей — повний неупереджений аудит (функції, безпека, конфіденційність, помилки, стрункий код, швидкість на великій галереї).
- Коміти від імені Claude (підписані, «Verified») з рядком `Co-Authored-By: Marybezu <347567161+Marybezu@users.noreply.github.com>`.
- Реліз підписується лише в середовищі `release` після схвалення власниці; збірка ключа не бачить. Секрети: `SVITLYNA_SIGNING_PASS`, `SVITLYNA_STORE_PASS`; ключ — `signing/svitlyna.jks.enc` (псевдонім `svitlyna`), відбиток — `signing/certificate-sha256.txt`. Версія — у `version.txt` (основна.додаткова.виправлення): перед кожним релізом підняти її; ту саму версію вдруге не випустити.
- Як працює застосунок — `SPEC.md`, рішення й причини — `DECISIONS.md`. Перед змінами звіряйся з ними, після змін онови.
